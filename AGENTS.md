# AGENTS.md — instructions for the attorney's AI assistant

You maintain each client's to-do list for an immigration attorney. She dictates things like
*"Maria needs her birth certificate and tax transcripts by Nov 15"*. You turn that into tasks in the
client's file, commit it, and give her the client link. The client opens the link on their phone and gets
a step-by-step list with drafted emails, call scripts, document tips, and checkboxes.

> ⚠️ **This repo is PUBLIC. EXAMPLE DATA ONLY.** Use invented names that end in "Example" (e.g. "Jose Example"). Never write
> real client names, A-numbers, SSNs, birth dates, addresses, phone numbers, emails, or case details. Leave
> `reminders.emailAddr` and `reminders.phone` empty. Real clients need the private backend described in `REMINDERS.md`.
> Every template is an **example** for the attorney to review. It is not legal advice.

## Where things are
| Path | What |
|---|---|
| `data/clients/<checklistId>.json` | **Source of truth**, one file per client checklist. Schema: `schema/client-checklist.schema.json` |
| `data/library.json` | Every built-in task template (EN/ES): email drafts, phone scripts, document tips, verified agency numbers/links. Generated from `js/library.js` |
| `data/clients/index.json` | Convenience index (regenerated by `scripts/cc.mjs`). Optional |
| `scripts/cc.mjs` | Zero-dependency CLI (Node 18+) that edits files safely and validates them |
| Client link | `https://moonyose.github.io/client-checklist/client.html?c=<checklistId>`. The page reads the file fresh from the GitHub API on every load, so a commit shows up within seconds (no Pages rebuild needed) |

## The file (schemaVersion 1)
```json
{

  "schemaVersion": 1,
  "id": "cl_jose_example",              // stable; file name = <id>.json; ^cl_[a-z0-9_]{4,40}$
  "rev": 3,                              // +1 on every change
  "createdAt": "2026-10-19T17:30:00.000Z",
  "updatedAt": "2026-10-19T18:02:11.000Z",
  "client": { "name": "Jose Example", "language": "es" },      // en | es
  "caseType": "naturalization",          // family_gc | naturalization | asylum | daca | other
  "message": "Short friendly note shown at the top (optional)",
  "attorney": { "name": "Example Immigration Law Office", "phone": "(555) 555-0100", "email": "office@example.com" },
  "reminders": { "email": true, "sms": false, "emailAddr": "", "phone": "", "time": "18:00" },   // coming in the real version
  "tasks": [
    { "id": "tk_9f2a1c7b3e", "library": "birth_cert", "due": "2026-11-15",
      "createdAt": "…", "updatedAt": "…" },
    { "id": "tk_47d0e2aa91", "library": "employment_letter", "due": "2026-11-02",
      "overrides": { "toName": "HR – ACME Corp (example)", "to": "hr@example.com" }, "note": "Ask for full-time status",
      "createdAt": "…", "updatedAt": "…" },
    { "id": "tk_c11b2e93f0", "library": null, "title": "Letter from his pastor", "custom": { …full content… },
      "createdAt": "…", "updatedAt": "…" },

  ]

```
(Comments are for explanation only. Real JSON has no comments.)

### Rules that keep the client's check-offs safe
* **Never change or reuse an `id`** (checklist or task). The client's progress is keyed by `checklistId + taskId` on their device.
* **Never store progress** (done/undone) in this file. The file is the *assignment*, and progress belongs to the client.
* **Add** a task by appending a new id. **Edit** one by changing its fields and setting its `updatedAt` to now. **Remove** one by setting
  `"deleted": true` and `updatedAt` to now (a tombstone). Keep the entry, don't splice it out.
* Bump the top-level `rev` by 1 and set the top-level `updatedAt` to now on every commit.
* Only one live task per library id. If it's already there, edit its due date instead of adding a duplicate.
* New ids: `tk_` + 10 random lowercase hex/alnum characters (e.g. `tk_3f9c0a1b7d`). New checklist: `cl_<firstname>_example` or `cl_` + random.
* Timestamps are ISO-8601 UTC (`2026-10-19T18:02:11.000Z`). Due dates are `YYYY-MM-DD`.

## Turning dictation into tasks
1. **Find the client file.** Match by name in `data/clients/index.json` (or list `data/clients/`). If there's no file, create one (ask for
   case type and language if you can't infer them. Default language `es` if she says the client speaks Spanish).
2. **Split** the sentence into items. One date in a clause applies to every item in that clause
   ("birth certificate and tax transcripts by Nov 15" means both are due 2026-11-15). Resolve relative dates ("in 2 weeks", "by Friday")
   against today in America/New_York. Month/day without a year means the next upcoming one.
3. **Map each item to a library task** (`data/library.json`, match on `keywords`/`title`). Common ones:

   | She says | library id | type |
   |---|---|---|
   | birth certificate / acta de nacimiento | `birth_cert` | document |
   | passport copy | `passport_copy` | document |
   | marriage certificate (has it) / (needs to order it) | `marriage_cert` / `marriage_cert_request` | document / email |
   | divorce decree, prior marriages | `prior_marriage_end` | document |
   | joint bank statements, lease, bona fides | `joint_financial` | document |
   | photos together | `relationship_photos` | document |
   | passport photos, 2x2 | `passport_photos` | document |
   | I-94, EADs, prior approvals | `immigration_docs` | document |
   | pay stubs, W-2s (sponsor) | `income_docs` | document |
   | DACA continuous residence proof | `daca_residence` | document |
   | employment / job letter | `employment_letter` | email |
   | school records, transcripts, registrar | `school_letter` | email |
   | affidavit / support letter from friends | `affidavit_request` | email |
   | court records, dispositions, arrests | `court_records` | email |
   | joint sponsor documents | `joint_sponsor` | email |
   | tax transcripts (online) / (by phone) | `irs_transcript_online` / `irs_transcript_phone` | online / phone |
   | FBI background check, rap sheet | `fbi_idhs` (online) · `fbi_phone` (questions, fee waiver) | online / phone |
   | FOIA, A-file | `uscis_foia` | online |
   | police clearance from home country | `police_certificate` | online |
   | order a US vital record | `vital_records_online` / `vital_records_phone` | online / phone |
   | call the consulate | `consulate_phone` | phone (placeholder number) |
   | call USCIS (only if she says so) | `uscis_contact` | phone |

   Use `overrides` for per-client details: `to` and `toName` for email recipients, `phone` for placeholder phone tasks.
   Use `note` for a short instruction ("We need 2023–2025"). The library templates already contain the full email drafts with
   `{{fullName}}`-style blanks that the client fills in on their phone, the call scripts, the "have ready" lists, and the document substitutes.
4. **If nothing fits**, write a **custom task with full content** (`library: null`, `title`, and `custom`, same shape as a library item).
   For example, an email to a pastor:
   ```json
   { "id": "tk_c11b2e93f0", "library": null, "title": "Carta de su pastor", "due": "2026-11-09",
     "custom": { "type": "email",
       "title": { "en": "Ask your pastor for a letter", "es": "Pida una carta a su pastor" },
       "summary": { "en": "A short signed letter saying you attend together.", "es": "Una carta corta firmada que diga que asisten juntos." },
       "toLabel": { "en": "Your church office", "es": "La oficina de su iglesia" },
       "fields": ["fullName", "spouseName", "phone"],
       "subject": { "en": "Letter request – {{fullName}}", "es": "Solicitud de carta – {{fullName}}" },
       "body": { "en": "Hello Pastor,\n\n…\n\n{{fullName}}\n{{phone}}", "es": "Hola Pastor:\n\n…\n\n{{fullName}}\n{{phone}}" } },
     "createdAt": "…", "updatedAt": "…" }
   ```
   * Custom types: `email` (subject, body, toLabel, bodyNote), `phone` (phone in E.164 `+1…`, phoneDisplay, hours, haveReady[], script[]),
     `doc` (where[], accepted[], tips[]), `online` (url `https://…`, steps[]), `custom` (text).
   * Blanks must be field keys from `data/library.json → fields` (fullName, dob, address, phone, email, aNumber, receiptNumber, spouseName,
     employerName, jobTitle, startDate, schoolName, schoolDates, courtName, caseNumber, friendName, sponsorName, taxYears, recordType, country, …).
   * Emails to employers, schools, courts, and government offices are written **in English** even for Spanish-speaking clients. Add a Spanish
     `bodyNote` that explains what the email says. Emails to friends and family go in the client's language.
   * **Never invent a phone number or URL.** Only use the verified agency contacts below, or contacts the attorney gives you.
     Otherwise mark it `"placeholder": true` and ask her for the number.
5. **Validate, commit, report.** Tell her what changed and give her the client link.

## Workflow A: you have a shell and git (e.g. a Grok Bot with a computer)
```bash
git clone https://github.com/moonyose/client-checklist && cd client-checklist   # or git pull
node scripts/cc.mjs list                                   # find the client
node scripts/cc.mjs new --name "Jose Example" --lang es --case naturalization --reminder-time 18:00
node scripts/cc.mjs dictate cl_xxx "birth certificate and tax transcripts by Nov 15; letter from his pastor by Friday"
node scripts/cc.mjs add cl_xxx --library employment_letter --due 2026-11-02 --to hr@example.com --to-name "HR – ACME (example)"
node scripts/cc.mjs add-custom cl_xxx --title "Carta de su pastor" --custom-json /tmp/pastor.json --due 2026-11-09
node scripts/cc.mjs edit cl_xxx tk_xxx --due 2026-11-20 --note "Certified copy, please"
node scripts/cc.mjs remove cl_xxx tk_xxx                   # tombstone
node scripts/cc.mjs show cl_xxx && node scripts/cc.mjs validate
git add data/clients && git commit -m "client(cl_xxx): add birth certificate + tax transcripts (due 2026-11-15)" && git push
```
`dictate` uses the same parser as the attorney page. Review its output, then use `add-custom` or `edit` to give custom tasks full content.
Every command bumps `rev` and `updatedAt`, keeps ids, and refuses to save an invalid file.

## Workflow B: GitHub connector only (e.g. Claude with a GitHub MCP server)
1. Read `data/library.json` once per session, then read `data/clients/<id>.json` (keep its `sha`).
2. Edit the JSON by following the rules above: new random ids, `updatedAt` on each changed task, tombstones, and top-level `rev`+1 and `updatedAt`.
3. Check it against `schema/client-checklist.schema.json`. The `validate client files` GitHub Action also runs on every push. Look at its result.
4. Write the file with the contents API (create, or update with the `sha`). Use the commit message `client(<id>): <what changed>`.
   Updating `data/clients/index.json` is optional.
5. Reply with a summary of what changed and the link `https://moonyose.github.io/client-checklist/client.html?c=<id>`.
